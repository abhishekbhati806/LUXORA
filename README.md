# ✦ LUXORA — Premium Hotel Booking

> **Stay somewhere unforgettable.**

A full-stack luxury hotel booking product: cinematic editorial front-end, a real Express +
MongoDB API with JWT sessions, live search with server-side filtering, a validated four-step
booking flow with atomic availability holds, traveller dashboards and an operations console.
Built as a premium startup product — not a CRUD template.

## Highlights

**Traveller experience**

- Cinematic full-screen hero with parallax, scroll-zoom and a glassmorphism search panel (Where / Check-in / Check-out / Guests).
- Interactive discovery (`/discover`): destination, price, rating, property type, amenities, room type and guest filters — every filter serialises to the URL (shareable), with grid/list views, sort, and a mobile filter drawer.
- Hotel detail pages: curated gallery with fullscreen lightbox and counter, amenities (Wi-Fi, pool, spa, restaurant, gym, parking, airport transfer…), verified reviews with rating breakdown, and a sticky booking widget computing nights + taxes + fees live, with invalid-date prevention.
- Four-step booking (Guest → Room → Review → Confirm) with a stepper, price-drift protection and a confirmation page: animated checkmark, booking code, QR pass (generated by a real QR encoder in `client/src/utils/qr.js` — not an image), and a downloadable pass.
- Wishlist with heart animations, persisted per user, empty states and remove-with-undo affordances.
- Split-screen auth with password visibility toggle, inline validation, loading/error/success states.

**Operations console** (`/admin`, admin role only)

- Live stats (hotels, bookings, revenue, users, occupancy) + SVG charts (monthly bookings, revenue, occupancy, popular destinations) computed server-side from real data.
- Full hotel CRUD with per-hotel room management, booking status management, review moderation and user administration.

**Backend**

- Real MongoDB (no mocks), Mongoose models with indexes and transactions for availability holds.
- JWT access tokens (15 min) + rotating httpOnly refresh cookies with server-side session revocation.
- bcrypt (cost 12), field-level validation, consistent `{ ok, data, meta? }` envelope, meaningful HTTP codes, rate limiting, security headers.
- Cloudinary-ready media pipeline: signed uploads when configured, local `uploads/` fallback, `501` responses when neither is available — no secrets in the repo.

**Engineering quality**

- Lazy routes + manual chunking (`react`, `motion`, `router`, `icons` split), LQIP data-URI blur placeholders, `content-visibility`-friendly layout.
- Accessibility: full keyboard flows, focus states, `aria-live` toasts, `prefers-reduced-motion` honoured globally (custom cursor, parallax, count-ups and reveals all degrade cleanly).
- SEO: per-route titles, descriptions and Open Graph tags.
- Every curated photograph is CC-licensed with attribution ([ATTRIBUTIONS.md](ATTRIBUTIONS.md)).

## Quick start

Requirements: **Node ≥ 18.18**, **MongoDB ≥ 6** (local or Atlas).

```bash
# 1. install (npm workspaces — runs for root, client and server)
npm install

# 2. configure
cp .env.example .env            # set JWT_SECRET / JWT_REFRESH_SECRET, then:
openssl rand -hex 32            # → paste for each secret

# 3. database (skip if you already run mongod; MONGO_URI defaults to 127.0.0.1:27017/luxora)
#    scripts/dev-mongo.sh starts a local mongod using ~/.cache paths (see the script)
bash scripts/dev-mongo.sh

# 4. seed 16 hotels across 7 destinations with rooms, users, bookings and reviews
npm run seed

# 5. run the API (:4000) and the Vite dev server (:5173) together
npm run dev
```

Open **http://localhost:5173** (dev) or **http://localhost:4000** (API; also serves `client/dist` after `npm run build`).

Single-command production build:

```bash
npm run build && NODE_ENV=production npm start
```

| Script | Does |
|---|---|
| `npm run dev` | API + client concurrently (`--watch` on the server, HMR on the client) |
| `npm run build` | Vite production build → `client/dist` |
| `npm start` | API in production mode, serves the built client on the same origin |
| `npm run seed` | Idempotent demo dataset (hotels, rooms, bookings, reviews, users) |
| `npm run seed:reset` | Wipe + reseed |
| `npm run lint` | ESLint over the client |

## Architecture

One request path, two layers of trust:

```
Browser ──▶ Vite dev server (dev) ─┐
                                   ├─▶ /api/v1 → Express → Mongoose → MongoDB
Browser ──▶ Express static dist ───┘        │
      (single origin in production)         ├─ middleware: rate limit → helmet → JWT auth → validation
                                            ├─ controllers return ok(res, data, { meta })
                                            └─ errors funnel into one handler → { ok:false, message, code, errors? }
```

- **Auth flow:** `POST /auth/login` returns a 15-min JWT (in memory / sessionStorage-adjacent store) and sets an httpOnly, SameSite=Lax refresh cookie. `api.js` intercepts `401`, calls `/auth/refresh` exactly once (rotating the refresh token; reused-token detection revokes the session family), replays the original request, then gives up and clears the session. Registration and login rate limits are separate and tighter.
- **Response envelope:** everything resolves to `{ ok, data, meta? }`. Paged lists keep `meta` (`page/limit/total/pages/hasNext`) end to end; the client unwraps single resources and preserves `{data, meta}` for lists.
- **Search:** filters + sort + pagination execute **in MongoDB** (text index, geo-less `location.city`, price/rating ranges, amenity/room arrays), not client-side. Availability for a date range is merged per hotel from a `Booking` aggregate so sold-out properties can't be picked.
- **State:** React contexts only (Auth, Toast, Wishlist, Search) + a 45-second in-flight GET cache in `services/api.js`. No state library needed at this scope.

The full governing document (design tokens, radii, type scale, spacing, a11y & motion policy) is **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)** — it was written before the code and the implementation follows it.

## Data model

Six collections (indexes noted where they matter):

| Model | Purpose | Key fields |
|---|---|---|
| `User` | accounts | name, email `unique`, passwordHash (select:false), role `traveller\|admin`, status, avatar, preferences, `refreshTokens[]` (rotation/revocation) |
| `Hotel` | properties | name, `slug unique`, tagline, city/country/region + coords, propertyType, starRating, rating/ratingCount, amenities[], description/policies, `images[]` (url, alt, slot), priceFrom (paise→int INR), tags, featured, archived, text index on name+city+tags |
| `Room` | bookable rooms | hotel ref, name, kind, beds, maxGuests, sizeSqft, pricePerNight, amenities, `partial unique index (hotel, roomId) where !deleted` |
| `Booking` | reservations | user, hotel, room refs, checkIn/checkOut, nights, units, guests, roomRate snapshot, subtotal/taxes(12%)/fees/total (server-computed), currency, status `pending→confirmed→cancelled/completed`, `confirmationCode unique` (`LX-XXXXXX`), leadGuest, payment (brand/last4 only — no card data), specialRequests, source, **`partial unique index (room, date-range overlap) for active statuses`** enforced via transactions |
| `Review` | verified reviews | user, hotel, rating 1–5, scores breakdown (6 axes), title/body, `status pending\|published`, helpfulCount, stayDate; `unique (user, hotel)` |
| `Wishlist` | saves | user `unique`, `hotels[]` (ordered, capped) |

Money is stored as integer INR everywhere; currency formatting is a presentation concern.

## API reference

Base: `/api/v1`. 🔓 public · 🔑 requires JWT · 👤 owner · 🛡 admin.
All endpoints answer the same envelope; errors carry `{ ok:false, message, code, errors?: [{field, message}] }`.

**Auth** `/auth` 🔓

| Method | Path | Notes |
|---|---|---|
| POST | `/register` · `/login` | validation + 409 on duplicate email; sets refresh cookie |
| POST | `/refresh` · `/logout` | rotation + family revocation on reuse |
| GET | `/me` 🔑 | current profile |
| PUT | `/me` 🔑 · `/password` 🔑 | update / change password (re-login required) |

**Hotels** `/hotels` 🔓

| Method | Path | Notes |
|---|---|---|
| GET | `/` | search: `city q checkIn checkOut adults children priceMin priceMax rating type amenities roomType sort page limit featured` → `{data[], meta}` |
| GET | `/meta` | facet counts for filter UI (destinations, types, amenities, price bounds) |
| GET | `/suggest` | typeahead (name/city) |
| GET | `/:idOrSlug` | detail + starting room + live `availability` for query dates |
| GET | `/:id/rooms` 🔑 | rooms with per-room availability |

**Bookings** `/bookings` 🔑

| Method | Path | Notes |
|---|---|---|
| POST | `/preview` | server-priced quote (nights, 12% tax, fees) — same rules as create |
| POST | `/` | `expected.total` must match server quote → `409 PRICE_CHANGED`; overlap checked transactionally → `409 NO_AVAILABILITY`; returns `{booking, quote}` |
| GET | `/` | `scope=upcoming\|past\|all`, paged |
| GET | `/:id` 👤 | full folio incl. QR payload |
| POST | `/:id/cancel` 👤 | free within 48h window per policy |

**Reviews** `/reviews` 🔓 GET, 🔑 write — GET `/hotel/:hotelId` (paged + summary/breakdown), POST `/` (one per stay, 409 on duplicate), PATCH/DELETE 👤, POST `/:id/helpful`.
**Wishlist** `/wishlist` 🔑 — GET, POST/DELETE `/:hotelId`, PATCH `/:hotelId/toggle` (returns ids + count).
**Users** `/users` — `/me/summary` 🔑 (counts, spend, next trip), `/me` DELETE 🔑 (password-confirm deactivate), `/:id` 🛡.
**Media** `/media` 🛡 — Cloudinary signed upload, asset registry, destroy; `501` with a clear code when unconfigured.
**Admin** `/admin` 🛡 — `stats`, `analytics?months=3..24` (bookings, revenue, occupancy, destination ranking), hotel CRUD + archive, room upsert/delete, `GET/PATCH bookings`, `GET/PATCH users`, `GET/PATCH reviews` (moderation), `DELETE reviews/:id`.
Health: `GET /health` → `{ status, uptime, database, version }`.

## Booking & pricing rules

- **Prices are never trusted from the client.** The quote (`nightly × units × nights + 12% taxes + fixed fees`) is recomputed at `POST /bookings`; a mismatch is `409 PRICE_CHANGED` and the UI re-rates in place.
- **Availability is the database's job.** Overlapping active bookings for a room are blocked by a partial unique index inside a transaction — concurrent double-books can't both win.
- **Date sanity:** check-out must be after check-in, nothing in the past, stay length ≤ policy — enforced in the widget (inputs disabled/min), validation middleware (422 with field errors) and the controller.

## Design system & motion policy

Warm-ivory canvas (`#F7F2EA`), espresso ink, champagne-gold accent, Fraunces (display) + Manrope (text); radius/spacing/shadow tokens are documented in `docs/ARCHITECTURE.md` and mirrored in `client/tailwind.config.js`.

Motion rule: **every animation carries information** (reveal = hierarchy, fade = route change, spring = state). Nothing loops for decoration. `useReducedMotion()` short-circuits parallax, cursor, count-ups and card motion globally; scroll reveals arm early (≤10% + 120px margin) so fast scrolling can never strand content invisible.

## Deployment

One process serves both API and SPA (`SERVE_CLIENT=true`), so a single dyno/container is enough:

```bash
npm ci && npm run build && npm start   # NODE_ENV=production, real JWT secrets, MONGO_URI=Atlas
```

- Set `CORS_ORIGIN`/`CLIENT_URL` to your HTTPS origin; refresh cookies automatically gain `Secure` in production.
- Configure Cloudinary vars for durable image uploads (hotels CRUD accepts them straight away); otherwise keep `uploads/` on a persistent volume.
- Run `npm run seed` once for demo data — or point at your own collections and skip it.
- Health check `GET /api/v1/health` for load balancers; add a scheduled `Booking` sweep to move past-date `confirmed` rows to `completed` (the occupancy metric already treats them correctly).
